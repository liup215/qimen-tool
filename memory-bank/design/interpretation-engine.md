# 奇门遁甲解释引擎设计文档

> 版本：v1.0
> 状态：设计稿，待实现
> 用途：指导解释引擎模块的开发与维护

---

## 1. 文档目的

本文档定义奇门遁甲 CLI 工具中**解释引擎（Interpretation Engine）**的设计原则、规则体系和接口规范。

解释引擎的目标是把排好的奇门盘面，转化为结构化、可解释、可追溯的分析报告。所有规则必须统一、固定、可验证，避免因流派差异或过度解读导致结果不可控。

---

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| **流程统一** | 所有问题类型走同一条分析流水线，唯一变化的是用神映射 |
| **规则统一** | 旺衰、生克、格局、资源、威胁的判定标准固定，不随问题类型变化 |
| **可解释** | 每一条结论都必须能追溯到盘面事实和规则依据 |
| **可验证** | 输出结构化数据，方便与经典案例对照测试 |
| **有限解读** | 只陈述盘面事实和规则映射，不做人生决策建议 |
| **简单优先** | 初版只支持转盘法、时家奇门，不做多流派切换 |

---

## 3. 解释引擎整体流程

```
输入：时间 + 问题类型 + 年命（可选）
           │
           ▼
    1. 确定用神集合
       （根据 questionType 查映射表）
           │
           ▼
    2. 计算各用神宫状态分
       （旺衰、门、星、神、格局）
           │
           ▼
    3. 分析日干宫与各用神宫的生克关系
           │
           ▼
    4. 识别资源符号与威胁符号
       （扫描全盘，判断与日干宫关系）
           │
           ▼
    5. 生成综合报告
       （JSON + Markdown 两种格式）
```

所有问题类型必须严格遵循以上流程，不允许在流程中插入特殊分支。

---

## 4. 用神标准化

### 4.1 核心约定

- **日干**永远代表问事人当前状态。
- **年命**（出生年天干）可选提供，若提供则作为自身状态的辅助参考。
- 如果问题类型不明确，工具只输出盘面概览，不做针对性分析。

### 4.2 问题类型与用神映射表

| 问题类型（questionType） | 主用神 | 辅用神 | 说明 |
|------------------------|--------|--------|------|
| `career` / `work` | 开门 | 值符、日干 | 工作、事业、职位 |
| `wealth` / `money` | 生门 | 戊、日干 | 财运、收入、投资 |
| `relationship` / `marriage` | 乙（女命）/ 庚（男命） | 六合、日干 | 感情、婚姻、合作 |
| `health` | 天芮星 | 日干、时干 | 健康、疾病 |
| `lawsuit` / `dispute` | 惊门 | 庚、值符 | 官司、口舌是非 |
| `travel` / `trip` | 景门 | 马星、九天 | 出行、远行 |
| `lost` / `missing` | 时干 | 玄武、日干 | 失物、寻人 |
| `study` / `exam` | 天辅星 | 日干、值符 | 学业、考试 |
| `general` / `overview` | 无 | 值符、日干、时干 | 仅盘面概览 |

> 注：性别相关的用神（如感情婚姻）可通过命令行参数 `--gender` 区分，默认按日干属性或中性处理。

## 5. 状态评分体系

### 5.1 评分维度

每个用神宫统一计算一个 **0-100 的状态分**，由四个固定维度加权构成：

| 维度 | 权重 | 计算依据 |
|------|------|---------|
| 五行旺衰 | 30% | 月令 + 宫位五行生克关系 |
| 八门状态 | 25% | 吉门/凶门/中性门 |
| 九星状态 | 25% | 旺相休囚 + 星性 |
| 八神与格局 | 20% | 吉神/凶神 + 空亡/入墓/击刑等状态 |

### 5.2 评分公式

```
score = 旺衰分 × 0.30
      + 门分   × 0.25
      + 星分   × 0.25
      + 神格分 × 0.20
```

### 5.3 状态等级

| 分数区间 | 状态等级 | 含义 |
|---------|---------|------|
| 80-100 | 旺 | 力量充足，事情易成 |
| 60-79  | 较强 | 条件不错，略有不足 |
| 40-59  | 平 | 力量一般，结果取决于关系 |
| 20-39  | 弱 | 力量不足，事情难成或需等待 |
| 0-19   | 衰 | 严重受制，事情不吉 |

### 5.4 特殊状态标记

| 状态 | 定义 | 影响 |
|------|------|------|
| **空亡** | 用神所在宫逢空亡 | 力量减半，事情不实、待时机、有变数 |
| **入墓** | 用神天干落入其墓库宫 | 受困，行动力受阻，难以发挥 |
| **击刑** | 用神天干与宫位地支相刑 | 受伤、损耗、不顺 |
| **门迫** | 门克宫 | 门的力量被压制 |
| **宫制** | 宫克门 | 门受宫压制 |

## 6. 生克关系分析

### 6.1 核心关系

解释引擎只分析一组固定关系：**日干宫 与 事用神宫**的五行生克。

| 关系 | 五行含义 | 解读模板 |
|------|---------|---------|
| 用神生我 | 用神宫五行生日干宫五行 | 所问之事对你有助益，机会偏正面 |
| 我生用神 | 日干宫五行生用神宫五行 | 需要你主动投入、付出，事成在你 |
| 用神克我 | 用神宫五行克日干宫五行 | 事情对你有压力、阻力或风险 |
| 我克用神 | 日干宫五行克用神宫五行 | 你能主导此事，但需费心费力 |
| 比和 | 两宫五行相同 | 双方势均力敌，结果看各自旺衰 |

### 6.2 关系强度修正

- 若用神空亡或入墓，生克力量减半。
- 若日干自身旺相，则抗克能力强、受生有力。
- 若用神旺相，则其生克作用明显。

## 7. 资源与威胁识别

### 7.1 资源符号

以下符号视为资源类符号：

| 符号 | 资源含义 |
|------|---------|
| 值符 | 贵人、领导、核心支持、官方资源 |
| 太阴 | 暗中助力、谋划、隐秘资源 |
| 六合 | 合作方、人脉、团队、客户关系 |
| 生门 | 财源、生机、收入来源 |
| 九天 | 高远助力、外地资源、扩张机会 |

### 7.2 威胁符号

以下符号视为威胁类符号：

| 符号 | 威胁含义 |
|------|---------|
| 白虎 | 压力、冲突、伤病、突发凶险 |
| 玄武 | 小人、盗贼、暗算、暧昧不明 |
| 螣蛇 | 纠缠、虚惊、反复、精神内耗 |
| 惊门 | 口舌是非、惊吓 |
| 伤门 | 损失、伤害、竞争 |
| 庚 | 阻碍、对手、阻隔之神 |

### 7.3 判断规则

对每一个资源/威胁符号，判断其落宫与日干宫的关系：

| 关系 | 效果 |
|------|------|
| 资源生日干 | 有助力，可借助 |
| 资源同日干（比和） | 助力存在但需争取 |
| 资源克日干 | 助力反成压力 |
| 资源空亡/入墓 | 助力不实 |
| 威胁克日干 | 有隐患，需防范 |
| 威胁生日干 | 压力转化为动力 |
| 威胁空亡/入墓 | 威胁减弱 |

规则库存放在 `internal/assets/` 目录下，所有规则以 JSON 形式维护：


## 10. 接口设计

### 10.1 Go 内部接口

```go
package interpretation

type QuestionType string

const (
    Career       QuestionType = "career"
    Wealth       QuestionType = "wealth"
    Relationship QuestionType = "relationship"
    Health       QuestionType = "health"
    Lawsuit      QuestionType = "lawsuit"
    Travel       QuestionType = "travel"
    Lost         QuestionType = "lost"
    Study        QuestionType = "study"
    General      QuestionType = "general"
)

type Engine struct {
    RuleLoader RuleLoader
}

// Interpret 根据盘面和问题类型生成解释报告
func (e *Engine) Interpret(plate *models.Plate, qt QuestionType, opts InterpretOptions) (*Report, error)

type InterpretOptions struct {
    YearStem string // 年命天干，可选
    Gender   string // male/female，可选
}

type Report struct {
    Meta          ReportMeta
    Self          SubjectState
    Target        SubjectState
    Relationship  Relationship
    Resources     []Force
    Threats       []Force
    Summary       string
    Caution       string
}
```

### 10.2 CLI 命令

```bash
# 生成 JSON 报告
qimen interpret --time "2025-06-05 15:30" --type career --format json

# 生成 Markdown 报告
qimen interpret --time "2025-06-05 15:30" --type wealth --format markdown

# 提供年命和性别
qimen interpret --time "2025-06-05 15:30" --type relationship --year-stem 乙 --gender female
```

## 11. 边界说明：明确不做

为保持工具简单可信，初版解释引擎明确不做以下事项：

| 不做 | 原因 |
|------|------|
| 多流派切换 | 只支持转盘法，避免规则冲突 |
| 自动人生决策 | 只输出盘面事实，不给出“该离婚/该投资”等建议 |
| 模糊推测 | 每条结论必须有盘面和规则依据 |
| 流年大运分析 | 属于八字命理范畴，超出奇门遁甲范围 |
| 多人同时比较 | 一次只分析一个问事人、一个问题 |
| 大模型自动生成解释 | 初版用规则引擎，保证可验证性 |
| 复杂风水堪舆 | 超出 CLI 工具范围 |

## 12. 实现步骤建议

1. **搭建规则库 JSON 文件**（spirits、doors、stars、question_types）
2. **实现 RuleLoader**，加载并校验规则文件
3. **实现用神解析器（ShenResolver）**：问题类型 → 用神集合
4. **实现状态评分器（StateScorer）**：计算用神宫分数
5. **实现生克分析器（RelationAnalyzer）**：判断日干宫与用神宫关系
6. **实现资源威胁扫描器（ForceScanner）**：扫描全盘资源与威胁
7. **实现报告生成器（ReportGenerator）**：生成 JSON 和 Markdown
8. **编写单元测试**：用已知经典案例验证解释结果
